# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Offline voice assistant on one NVIDIA GPU (RTX 3070 Ti, 8 GB): RealtimeSTT (faster-whisper + Silero VAD) → Ollama (streaming) → RealtimeTTS + Kokoro. Two front ends share one brain: local mic/speakers (`assistant.py`) and a browser on any device (phone, tablet, PC) over HTTPS/WebSocket (`web.py` + `web/index.html`). User-facing docs: `README.md`, architecture explainer: `HOW_IT_WORKS.md`, work list: `ROADMAP.md`.

## Commands

```bash
bash setup.sh            # one-time: apt deps, Ollama + model pull, .venv from requirements.txt
./run.sh                 # local mode (mic + speakers; typing + Enter also works)
./run.sh --web           # web mode (browser on any device), serves https://<ip>:8443 (self-signed cert auto-created in certs/)
sudo ./install-service.sh [--uninstall]   # optional: web mode as a systemd service at boot
VOICE=am_michael LLM_MODEL=qwen2.5:7b MEMORY=0 ./run.sh   # all config is env vars (CONFIG block in assistant.py)
.venv/bin/python -m py_compile assistant.py web.py memory.py   # quick syntax check
```

Always launch via `run.sh`: it sets `LD_LIBRARY_PATH` to the pip-installed cuBLAS/cuDNN, without which faster-whisper fails.

There is no test suite or linter. Changes have been verified with throwaway scripts (keep them in the scratchpad, not the repo):
- **Brain/memory without audio:** `import assistant` and consume `assistant.llm_stream("...")`; set `MEMORY_FILE` to a scratch path first (real file: `memory/memory.md`) so the user's real `memory.md` isn't touched.
- **Web mode without a device:** start `./run.sh --web`, connect a `websockets` client to `wss://localhost:8443/ws` (cert verification off), send 16 kHz s16le PCM (e.g. `espeak-ng … | ffmpeg -ar 16000 -ac 1 -f s16le -`) or `{"type":"text","text":…}`, and collect JSON events + 24 kHz PCM audio.
- **Console typing:** `(sleep 45; echo "question") | timeout 75 ./run.sh`.
- **Voice changes:** render WAVs with `TextToAudioStream(..., muted=True).play(output_wavfile=...)` and let the user compare by ear.

## Architecture

- **`assistant.py` is also the shared library.** `web.py` imports its config, `llm_stream`, `make_recorder`, `PLAY_OPTIONS`, `listen`, `stop_llm`. Tune STT/TTS/LLM settings there once; both modes pick them up.
- **Inbox pattern:** spoken text (`listen()` thread around `recorder.text()`) and typed text go into one `queue.Queue` as `("voice"|"typed", text)`; a single conversation loop consumes it. Typed messages always interrupt (`interrupt(force=True)`), voice only when `BARGE_IN=1`.
- **`llm_stream` is a generator fed to `tts.feed()`** through `speakable()` (strips `* _ ` # ~` so Kokoro doesn't say "asterisk"; the page and the log get the raw markdown, rendered by `format()` in index.html); RealtimeTTS pulls tokens and synthesizes per sentence. Conversation history is a module-level list (`history[0]` is the system prompt, rebuilt with memory facts). Single user only.
- **Web mode:** recorder runs with `use_microphone=False` and gets `feed_audio()` from the WebSocket; TTS runs `muted=True` with `on_audio_chunk=send`, so audio is streamed (faster than real time) instead of played. Worker threads talk to asyncio via `loop.call_soon_threadsafe` into a per-connection queue (`pump`) to keep message order. Because the browser buffers audio ahead of the server, interrupts also send `{"type":"stop"}` and the page ignores audio until the next `{"type":"reply"}`. Replies are spoken only while the page's mic is on (page sends `{"type":"mute"}`); when muted the server skips Kokoro and just drains the generator in a thread.
- **Memory (`memory.py`):** after a reply, if `worth_checking()` passes (first-person statement or remember/forget; questions skipped), a background thread asks the same Ollama model for `{"add":[…],"remove":[…]}` JSON and updates `memory.md`. Removals are ignored unless the user said a forget-word or new facts were added — small models otherwise delete facts on unrelated turns. These guards were tuned against real `llama3.2:3b` failures; keep them. Manual edits (`Memory.remember/edit/forget/forget_all`, wrapped by `assistant.memory_add/edit/remove/clear`; console `/memory /remember /forget N|all`, the web page's ☰ panel (three-line menu icon) via `memory`/`memory_add`/`memory_edit`/`memory_remove`/`memory_clear` messages; the page holds re-renders while a fact is being edited) share the module `_lock` with the background updater. Every change goes through `assistant.memory_changed(added, removed, learned)`, which rebuilds `history[0]` and calls the `on_memory_change` hook; web.py sets it to send `{"type":"memory","facts",…,"learned"}` (learned → a chat note on the page). The page removes facts by exact text, not index. Facts are kept newest first (file, panel, `/memory`, prompt): new ones go on top, edits stay in place; files without the `# Newest first.` header line are from before and get flipped once on load.

## Gotchas (learned the hard way)

- Wake word (console: `/wake` command, typed lines starting with `/` are commands; web page: the Wake word switch in the ☰ menu → `{"type":"wake_mode"}`; both call `assistant.set_wake_mode()`, which toggles `recorder.use_wake_words` live — web.py imports it as `set_recorder_wake_mode` because it has its own `set_wake_mode`; `wake_word_options()` in assistant.py; `on_wake` hook lets web.py chime in the browser instead of on the PC): openwakeword 0.6 is installed with `--no-deps` (it declares tflite-runtime, which has no py3.12 build; we use the ONNX engine) — so `setup.sh` installs requirements with `--no-deps`. Always pass `openwakeword_model_paths`, or every built-in model (alexa, mycroft…) triggers. `on_wakeword_detected` fires per audio chunk — keep the debounce. The follow-up window is RealtimeSTT's `wake_word_activation_delay`, switched at runtime: 0 at startup (else the first FOLLOW_UP seconds accept any speech), set to FOLLOW_UP with `recorder.listen_start` reset when a reply finishes playing (TTS `on_audio_stream_stop`, hooked after "Ready."), back to 0 in `on_wakeword_timeout` (`close_follow_up`). That callback fires both when the window ends and when the wake word is heard but no speech follows within `wake_word_timeout` (RealtimeSTT clears that timer when recording starts); it plays the `SLEEP_NOTES` falling tone (`SLEEP_SOUND`), skipped while a reply is still playing (console `tts.is_playing()`, page `sources.length`) because a long reply can outlast the window. During a spoken reply `hold_window()` sets the delay to 24 h (only with `BARGE_IN`), so plain speech barges in even in wake mode (browser echo cancellation squashes the user's voice during playback, and openWakeWord missed "Hey Jarvis" then); interrupts call `open_follow_up()` (web: only if `Client.replying`, cleared on `played`/interrupt). `wake_word_options(on_detect=interrupt)` makes the wake word itself stop a reply; `listen()` strips a leading wake phrase (`WAKE_PHRASE`), and an empty result sends nothing. In web mode the server's TTS finishes before the browser does, so the server sends `end`, the page answers `played` when its playback queue is empty, and only then `open_follow_up()` runs.
- Barge-in must use `on_vad_start` (actual speech). `on_vad_detect_start` fires whenever the recorder *starts listening*, which killed every reply.
- Every Ollama call must send the same `LLM_OPTIONS` (`num_ctx`), or Ollama reloads the model. Requests use `keep_alive: -1`, so models stay in VRAM until `ollama stop <model>`.
- Two GPUs (since 2026-10): RTX 3070 Ti (index 0) runs Ollama `qwen3:8b` + Whisper; Quadro T1000 (index 1, 4 GB, no tensor cores) runs Kokoro and the desktop (monitor on the T1000 + BIOS primary display = T1000; without the BIOS change the desktop still renders on the 3070 Ti). Set in `local.env` (git-ignored, machine-specific; read by `run.sh`, command-line env wins): `WHISPER_GPU=0 STT_COMPUTE=int8_float16 KOKORO_GPU=1 LLM_MODEL=qwen3:8b`. Code defaults stay one GPU + `llama3.2:3b` + `float16`. `run.sh` exports `CUDA_DEVICE_ORDER=PCI_BUS_ID` so indices match nvidia-smi. Whisper uses RealtimeSTT's `gpu_device_index=WHISPER_GPU`; Kokoro has no device option, so `make_voice()` loads it inside `torch.cuda.device(KOKORO_GPU)` (inference follows the model's device). Measured for a 3.3 s sentence: Whisper on the 3070 Ti next to qwen `int8_float16` 141 ms (5.9 GB used), `float16` 159 ms (6.9 GB); on the T1000 `int8` 1.7 s, `float16` 7.1 s — too slow, the user rejected it. Kokoro on the T1000: first audio 0.10 s. English only (the user's choice): Whisper language setting is `STT_LANGUAGE` (not `LANGUAGE`, a Linux locale variable), default `en`. `large-v3-turbo` was tried on 2026-10-19 (182 ms, +1157 MiB; English as good, also transcribes Russian) and dropped; it's still in the HF cache. Kokoro can't speak Russian, and qwen3 answers in the user's language whatever the prompt says. Don't change model/STT settings unasked. Ollama is pinned to the 3070 Ti (applied 2026-10-18) by a systemd drop-in `/etc/systemd/system/ollama.service.d/gpu.conf` with `CUDA_VISIBLE_DEVICES=<3070 Ti UUID>` — Ollama can't see the T1000. Check: `systemctl show ollama -p Environment`.
- VRAM: 3070 Ti ≈6.7 GB used (qwen3 5.5 + Whisper 1.2), ~1.1 GB free (qwen2.5: ~2.3 GB free); T1000 ≈1.1 GB (Kokoro 0.7 + desktop). Only one mode (console or web) can run at a time. `qwen2.5:7b`, `llama3.2:3b` and `qwen3:8b` are installed — don't remove any. qwen3:8b is the model in use (since 2026-10-18): before the pinning it split across both GPUs and was slow; pinned, first word 54–267 ms, same speed as qwen2.5. All Ollama requests send `"think": false` (qwen3 would otherwise reason silently before answering; other models ignore it).
- RealtimeTTS 0.8.10 already hands Kokoro whole sentences; bigger `minimum_*_length` values change nothing. `comma_silence_duration` only applies when a piece ends at a comma; the audible pause is `SENTENCE_PAUSE`.
- Offline: `run.sh` exports `HF_HUB_OFFLINE=1` once `~/.cache/huggingface/hub/models--hexgrad--Kokoro-82M` exists (otherwise Kokoro/Whisper ping Hugging Face on every start and print the HF_TOKEN warning). New HF models need `HF_HUB_OFFLINE=0` once. Verified offline by running with `HTTP(S)_PROXY=http://127.0.0.1:9` and `NO_PROXY=localhost,127.0.0.1`: Silero (torch.hub cache) and openWakeWord (downloaded models) also stay local.
- Auto-start: `install-service.sh` fills `@USER@`/`@DIR@` in `voice-assistant.service` (template in the repo) and installs `/etc/systemd/system/voice-assistant.service` (After/Wants `ollama.service`, `KillSignal=SIGINT` for a clean shutdown, `Restart=on-failure`). The unit sets `VA_SERVICE=1`; without it, `run.sh` exits if the service is active (one copy fits on the GPU) — so when testing with `./run.sh`, check `systemctl is-active voice-assistant` first. Logs: `journalctl -u voice-assistant`.
- Browsers require HTTPS for the mic, hence the self-signed cert. The server binds `0.0.0.0`. Password (`WEB_PASSWORD`, empty = open + startup warning): websockets 16 only parses GET, so login is `GET /login` with the password URL-encoded in an `X-Password` header; success sets cookie `va_session` = HMAC-SHA256(`certs/session.key`, password) (`Secure; HttpOnly; SameSite=Strict`, 1 year), so restarts keep devices logged in and a new password logs all out. `http()` (async `process_request`) refuses `/ws` without the cookie; the page calls `/auth` (204/401) before every (re)connect to decide between socket and lock screen; `/logout` clears the cookie; its item is in the ☰ menu (with Wake word, Memory (hidden with `MEMORY=0`) and New conversation → `{"type":"new_conversation"}` → inbox `("new", "")` → `new_conversation()`, console `/new`). The mic mute button disables the browser's audio track, so the server keeps getting (silent) audio and an utterance in progress ends normally; replies keep playing. Wrong tries: 1 s delay, 5 per IP → 30 s lock (429). The login layer needs no GPU: test it by importing `web` and serving `web.http` with a dummy handler on another port.
- `requirements.txt` is a full `pip freeze` (with the cu124 extra index header). Upgrade deliberately: change, test, re-freeze, keep the header.
- Privacy: the service's stdout goes to the systemd journal (outside the project, kept for months), so `PRINT_CHAT` (default off when `VA_SERVICE` is set) gates every print of conversation content: tokens in `llm_stream`, You/AI lines in both loops, memory facts (`Memory(verbose=)`, `memory_add/remove/edit`). web.py prints `💬 <source> message` instead. Keep new prints of user content behind `PRINT_CHAT`. `realtimesst.log` has no transcripts (checked), only debug events.
- `settings.json` (`SETTINGS_FILE`, project folder, git-ignored): `{"profile", "save_log", "wake_word", "memory"}` (missing keys are filled in at start), loaded at import (`assistant.settings`), each change written via `save_setting()` (tmp file + rename). An old `profile.txt` is migrated once and removed. Wake word state is server-side and shared: `set_wake_mode(recorder, on, save=True)`; both modes start with `settings["wake_word"]` (default off); web sends it in `hello` and echoes `{"type":"wake_mode"}`; the page no longer uses localStorage for it. When testing, set `SETTINGS_FILE` to a scratch path.
- Use memory switch: `assistant.memory_on` (`settings["memory"]`) gates `system_prompt()`'s memory part and the background learning in `llm_stream`; `set_memory_use()` (console `/memory on|off`, web `{"type":"memory_use"}`) rebuilds `history[0]` at once. Mid-conversation that alone isn't enough (qwen3 repeats its earlier "I don't know your name"), so it also appends a system note starting with `MEMORY_NOTE` — on: the facts listed again, off: don't use them — after removing any earlier such note (otherwise the facts stay in the conversation after "off"). Measured: 10/10 each way. The Memory panel still edits facts while it's off. `MEMORY=0` (no `Memory` object) hides both menu items.
- Private mode: `assistant.log_on` (starts as `LOG` and `settings["save_log"]`) gates `log_turn`/`log_event`; `set_logging()` from console `/log on|off` or the web menu (`{"type":"log","value"}`, echoed back to the page, sent in `hello`). Saved in settings.json, server-wide; memory is not affected.
- Conversation log: `log_turn()` in assistant.py, called at the end of `llm_stream` (the one path for both modes); callers pass `source="voice"|"typed"`. Files `LOG_DIR/YYYY-MM-DD.md`, session header per run. When testing, set `LOG_DIR` to a scratch path (and `MEMORY=0`) so the user's real logs and memory stay clean.
- Profiles: `profiles/<name>.md` = optional `key: value` header (`label voice speed pause temperature model`) + blank line + prompt; `load_profile()` falls back to the env settings for missing keys, rejects names outside `[\w-]+` and names starting with `_` (`_template.md` documents the keys and is not listed). Bad numbers are skipped; `check_profile()` (startup + switch) falls back to `VOICE` if the voice isn't in the HF cache/downloadable and to the current model if Ollama doesn't list it — otherwise Kokoro would fail mid-reply. `apply_profile()` swaps the module globals `profile`/`LLM_MODEL`, temperature, `PLAY_OPTIONS` pause, Kokoro voice/speed, replaces only `history[0]` (the conversation continues on switch; memory shared; `new_conversation()` / `/new` resets `history` and the log session) and writes `*HH:MM — switched to X*` into the log (`log_event`); on a model change it unloads the old model (`keep_alive: 0`) first, as only one fits. Kokoro builds a pipeline per accent lazily on the *current* GPU, so `set_profile_voice()` pre-builds it inside `torch.cuda.device(KOKORO_GPU)`. Web: profile switches go through the inbox as `("profile", name)` so they serialize with replies; web.py reads `assistant.profile` (not an imported copy). The last switched-to profile is saved in `settings.json` and used at startup unless `PROFILE` is set; a missing profile file falls back to `default`. In offline mode only downloaded voices work (af_heart, af_bella, am_michael, bf_emma). Web editor: `profiles_event()` sends the list (`profile_for_editor`, model "" = no `model:` line = `BASE_MODEL`), template, `available_voices()` (HF cache) and `installed_models()`; `write_profile()` validates (ASCII name, `PROFILE_RANGES`, installed model, non-empty prompt) and writes all keys; `profile_save` of the active profile queues `("profile_reload", name)` → `apply_profile()` (same as a switch: keeps the conversation). `▶ Test` (voice, speed, pause from the editor, unsaved) queues `("preview", json)`: `set_voice()` on the shared Kokoro engine, blocking `tts.play`, then `set_profile_voice()`; the page plays it even while muted (`preview`/`preview_end`, ignores `end`). Defaults come from `BASE_MODEL`/`BASE_TEMPERATURE`, not the current profile's. `think: on` → `llm_stream` sends `"think": thinking()` (profile wants it and `model_can_think()`, cached from Ollama `/api/show` capabilities); web sends `{"type":"thinking"}` so the page shows *Thinking…* until the first token; memory extraction and warm-up always send `think: false`. `silence` sets `recorder.post_speech_silence_duration` (read live; `apply_profile(recorder=)`), min 0.3 because `early_transcription_on_silence` is 0.2. `write_profile` always writes every setting (`think: off`, `silence: …`) so files show the full set, except `model`: without one it writes the comment `# model: (not set = LLM_MODEL from local.env)`, so changing LLM_MODEL still applies. Git tracks only `profiles/default.md` and `_template.md` (`.gitignore`: `profiles/*` + exceptions).
- Not in git (keep it that way): `memory/` and `conversations/` (personal data), `settings.json` (+ `.tmp`), `local.env`, `certs/`, `voice-samples/`, `.venv/`, logs.

## Working with this user

- Wording: user-facing text says **device** ("Device connected", "Log out of this device") and **web mode** (= `./run.sh --web`), never "phone"; code and comments say **browser**/**page** — "device" in code means a GPU (`gpu_device_index`, `torch.cuda.device`).

- Exploratory questions ("is it possible…", "what do you think…") get discussion only — no commands, not even read-only checks — until they say to build.
- `ROADMAP.md` is the running work list: pick from it, move finished items to Done, add agreed ideas.
- Commit only when asked. Remote: github.com/suhrobina/voice-assistant (**public**) — push only when asked. Commits use the GitHub noreply email (repo config); never commit personal data (memory, conversations, local.env, settings.json, certs, own profiles).
